## WHAT TESTING FOUND IN MY OWN WORK

* **A real bug in M2, found by the new fixture.** Redaction by header name replaced `Access-Control-Allow-Credentials: true` (the name
  contains "credential"), so the credentials branch of rule R-CORS-01 could never fire on stored data and a CORS review lost the one fact it
  needs. Fixed for that exact name only (D-E72), with a regression test through the real pipeline that fails without the fix.
* **A hostile spec document carries a sentence in its title.** The spec is stored as an artifact (it holds no response value), and a test
  shows its text reaches no table and no observation field; only the artifact holds it, as the document it is.
* **Layered checks hid each other.** The path-template check and the params-must-match-the-path check both refused a bad path, so removing
  either alone changed nothing (the mutation run found it). The tests now also give a bad path no params list, so only the path rule can refuse it.
* **The mutation run left five alive, all in my tests:** the 50-element cap on an array was not distinguishable because every element had the same
  shape; a path-level `parameters` object was only tested as a list; the stricter of the two response limits was tested with two equal limits;
  the explicit `ROLLBACK` of a failed rebuild was hidden by the connection's own rollback on close (the test now looks on the same connection);
  and the path-template check was hidden by the params check (above).

## WHAT THIS DOES NOT SHOW

* **Anything about a real API.** The packs are mine, no API was contacted and no credential was read (SE-37). Whether two principals'
  answers show an authorization flaw is a person's call, or `boundarycheck`'s.
* **That a shape cannot reveal.** A short key that is itself an identifier is stored as written (SE-38); the three flags are pattern
  matches (SE-39).
* **That migration `0004` is safe on a database that matters to you.** It is tested on a database holding two real runs (every row, the
  schema, the audit chain and the trigger are compared before and after; it is atomic; a copy is made first), and the only data it
  has ever touched is synthetic. It is still the first migration that rewrites records, so it waits for your approval.
* **Mutation testing shows the tests notice these bugs, not that no other bug exists.**
