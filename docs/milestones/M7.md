## WHAT RESEARCH AND TESTING FOUND

* **My own memory of the benchmarks was out of date, in two places.** I knew the web Top 10 as the 2021 list; the current edition is 2025 (Security
  Misconfiguration is A02, Injection is A05, SSRF is folded into A01). I knew the LLM list as 2025; a **2026 edition** exists and replaces it. Its
  ten risks were not on any web page I could read (only in its PDF), so I read the PDF's contents: System Prompt Leakage became **Hidden Context
  Exposure (LLM08)** and Improper Output Handling moved to LLM10. This is the strongest argument for keeping the list as dated data.
* **The host-cap test had to be rewritten.** The web-targets list is itself capped at 20 entries, so with the new cap the web list was refused
  first and the test never reached the host cap; it now reaches 20 through web and API targets together.
* **A clock set before the check date printed "-2 days ago".** It is now shown as 0; a mutant that removes the clamp is killed.
* **A coverage branch was missing** for a finding whose rule the catalogue no longer knows (a draft stored under a renamed rule): its categories are
  simply absent, never invented. Now tested.

## WHAT THIS DOES NOT SHOW

* That the mapping is *right*. It is my judgment of the closest category for each rule, with a note where the fit is loose, and you review it.
* That the tool "covers" any OWASP list. Most categories have no rule (`benchmarks status`); the tool labels what it checks.
* That the editions are current beyond the day they were read (2026-11-22). The LLM PDF I read says "publication date to be set" in its own
  front matter; its web page says August 3, 2026.
