## WHAT TESTING FOUND IN MY OWN WORK

* **A secret leak (found by a coverage test, not by a review):** a private-key block that began with a *second* `BEGIN` marker left the real key
  body in the stored text, because the end of a block was found by searching for the text `PRIVATE KEY-----`, which the second `BEGIN` line
  also ends with. The end marker is now the whole `-----END ... PRIVATE KEY-----` line. Regression tests, and a mutant that restores the bug.
* **A crash:** a certificate whose `san_dns` held a non-text entry raised `AttributeError` in the TLS adapter instead of recording a
  `parse_error`. A comprehension tested the wrong type. Rewritten as a loop; tested.
* **A valid file refused:** a `robots.txt` with 50 long `Disallow` lines produced parsed facts over the schema's 8 KiB and the whole observation
  became a `parse_error`. The parsers now shorten the longest list (last entries first) until the facts fit.
* **Wrong tests of mine, caught by the code:** I expected an absurd token count to be refused; the parser already drops it to `null`, which is better.
  A test of mine leaked an SQLite connection (`with sqlite3.connect()` commits but never closes); found by a `ResourceWarning`.
* **Mutation testing:** 28 of the 236 mutants in the first M2 run survived. 23 were real gaps in my tests: a limit checked against the very constant it
  tested (so changing the constant changed the test), a header word never exercised, an e-mail compared case-sensitively, a redaction count never asserted,
  `U+2028` never fed to a line parser, a source hash that could have held a secret from a body, a probe read in the wrong API style. All now have an explicit
  test. Two were equivalent and are removed with a comment in `tools/mutation.py` (a boolean status is the integer 1, which the range check refuses; a
  non-mapping certificate is refused by the schema as well). Three guarded a property twice (the run and the schema, or the run and the repository) so
  removing one layer changed nothing; they now remove both layers, as in M1. All of them die.
* **The global socket guard was too broad:** it blocked asyncio's own `AF_UNIX` socket pair. It now blocks network families only, and a test proves
  that network sockets of both families are refused while a local pair still works.

## WHAT THIS DOES NOT SHOW

* **Nothing has touched a network.** There is no live adapter (M5). The packs are written by me, so they test the adapters against what I thought
  responses look like, not against what a real server sends.
* **Redaction is best effort** (SE-05, SE-20): a secret in a shape no pattern knows is stored. Review a run with `observations show` before sharing it.
* **Nothing is correlated or drafted** (M3): exit code 0 means the collection was complete, not that nothing is wrong (SE-19). `state: DRAFTED` is the end of the
  pipeline today, with nothing drafted.
* **The probe texts do not exist yet** (SE-16): an AI probe is answered from a recorded reply.
* **Sequential collection** (SE-22): parallelism arrives with live mode.
* **Mutation testing shows the tests notice these bugs, not that no other bug exists.**
